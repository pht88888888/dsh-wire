# 会让人用不了的每一种情况

> 这张表是「从装插件到日常使用」的完整链条，每一环列出可能断掉的地方，
> 以及插件现在怎么处理它。目标是：**用户不需要来问我**，界面上就能看到
> 断在哪、为什么、下一步做什么。
>
> 标记：✅ 已自动处理并给出结论 ／ ⚠️ 能检测出来并提示，但必须用户动手 ／ ⬜ 待处理

## 一、装插件

| # | 情况 | 用户看到的 | 现在怎么处理 |
|---|---|---|---|
| 1.1 | npm 装到缓存旧版（只写包名） | 版本号是旧的 | ✅ 状态条右上角常显版本号；README 要求带 `@版本号` |
| 1.2 | 装完没重启 DSH | 设置页没有「远程配对」 | ⚠️ README 与安装说明里写明必须重启 |
| 1.3 | 找不到设置入口 | — | ✅ README：账号菜单 → Settings → 远程配对 |
| 1.4 | 全新 DSH 的 Preview Notice 弹窗挡住 | 只看到一块说明弹窗 | ⚠️ DSH 自身行为，点 Continue 即可 |

## 二、cloudflared 这个二进制

| # | 情况 | 后果 | 现在怎么处理 |
|---|---|---|---|
| 2.1 | 根本没装 | 隧道起不来 | ✅ 设置页直接给「下载 cloudflared」按钮，下到插件自己的目录 |
| 2.2 | 装了但不在 PATH | 同上 | ✅ `findCloudflared` 依次找 配置指定 → 插件自带 → PATH |
| 2.3 | 装的是 `.cmd`/`.bat` 包装脚本（Windows 常见于包管理器） | `spawn` 直接 ENOENT，进程根本起不来 | ✅ spawn 失败且是 Windows 时用 shell 重试一次 |
| 2.4 | 版本太老，不支持 `tunnel --url` | 启动即报错退出 | ✅ 探测时跑 `--version`，把版本号显示出来 |
| 2.5 | 机器上有全局 `config.yml` 接管 | 连到别人的命名隧道，地址 404 | ✅ 强制 `--config` 指向插件自己写的空文件，隔离全局配置 |
| 2.6 | 上次的 cloudflared 没退干净 | 可能端口/连接冲突 | ✅ 诊断项会列出系统里残留的 cloudflared 进程 |

## 三、启动隧道（最容易静默失败的一段）

| # | 情况 | 用户看到的 | 现在怎么处理 |
|---|---|---|---|
| 3.1 | UDP 7844 被丢（QUIC） | 进程活着、不报错、地址永不出现 | ✅ 默认 `--protocol http2` 走 TCP 443 |
| 3.2 | 443 也被封（公司网/校园网代理） | 同上 | ⚠️ 诊断项会检测到 443 不通并说明原因 |
| 3.3 | DNS 解析不了 `*.argotunnel.com` | 同上 | ⚠️ 诊断项逐个解析 Cloudflare 的域名 |
| 3.4 | 系统代理 / VPN 劫持 | 同上或证书错误 | ⚠️ 诊断项读 `HTTP_PROXY` 等环境变量并提示 |
| 3.5 | metrics 端口 20242 被占 | 启动后退出 | ✅ 显式指定 `--metrics 127.0.0.1:0`，让系统分配 |
| 3.6 | 防火墙弹窗被拒 | 连不上 | ⚠️ 诊断项检测 443 不通时提示检查防火墙 |
| 3.7 | 杀毒软件拦截 | 进程被秒杀 | ⚠️ 日志里能看到退出码，界面会显示 |
| 3.8 | 快速隧道限流（同 IP 建太多） | 报 `ERR Failed to request quick Tunnel` | ✅ 这条 ERR 会被抓出来原样显示 |
| 3.9 | 输出格式变了，正则抓不到地址 | 静默卡住 | ✅ 30 秒超时 + 把 cloudflared 原话显示出来 |
| 3.10 | 本机自己连不上隧道（自检失败） | — | ✅ 仍然把地址交出去，标记为未验证 |
| 3.11 | spawn 失败（ENOENT/EACCES） | 静默 | ✅ 上报到界面 |

## 六点五、实测新发现（0.7.0 已修）

| 现象 | 真因 | 处理 |
|---|---|---|
| 连不上，报 `target is not defined` | 0.6.8 的切网提示用了作用域外变量，catch 里抛 ReferenceError，把真实错误盖掉 | ✅ 改成存上一次成功定位的地址 |
| 隧道地址有、手机访问 530，cloudflared 进程却是活的 | 进程活着但隧道连接已死，onExit 不触发就永不重建 | ✅ 每 90 秒自检自己的公网地址，连续三次失败即重建 |
| 手机上装完看到的是「输入配对码」面板 | 角色被判成电脑端，去下载 cloudflared 起隧道 | ✅ 加认 ANDROID_ROOT / ANDROID_DATA / /system/build.prop |
| 配对码过期后点「连接」只说过期 | 流程正常，但用户不知道该去点「重新生成配对码」 | ✅ 报错里直接写这一步 |
| 全新电脑 + 全新手机，手机端一片空白「Choose workspace」 | `workspace.follow` 包装里远程会话为空就早退，导致「电脑」工作区永远不建 | ✅ 不管有没有远程会话都建工作区，用户能看到它并发第一条消息 |

## 七、仍然只能靠用户动手的

- **防火墙 / 杀毒软件**：插件不能替用户放行，只能检测到「443 不通」并说清是这一层。
- **公司网完全封锁外网 443**：任何隧道方案都不行，只能用局域网直连串。
- **DSH 自身的行为**（Preview Notice 弹窗、锁屏后 JS 冻结）：不属于插件范围。
